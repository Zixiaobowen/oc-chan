最终结构与执行模型

  • crates/oc-core/：与 Tauri 无关的 Rust 业务核心。类型、验证、资源预算、有界 IO、采集器、实时会话、调度/历史、事件/通知策略、设置、诊断、插件市场及更新状态机。
  • crates/oc-plugin-sdk/：版本化原生插件消息契约与 Rust SDK。仅公开 DTO、宿主 IO 请求、取消及生命周期协议；不依赖核心内部实现。
  • plugins/system-monitor/：Rust 官方独立采集插件及 manifest。系统监控仍通过市场安装，默认不安装，不编译进核心。
  • src-tauri/：Tauri 桌面宿主、严格 command 边界、主窗/托盘/恢复窗、原生桥接、应用生命周期及更新安装入口。
  • src/renderer/ 与 src/shared/：保留 UI 和渲染纯逻辑。集中 desktop 适配器通过 @tauri-apps/api 调用有限命令与事件；替换旧 preload，生产页面不含 Node 能力。
  • native/：Swift Tern helper 与 C ABI 的 AppKit/UserNotifications/ServiceManagement/IOKit 小型桥接。平台行为保留，N-API 删除。
  • scripts/：前端构建、Cargo/Tauri 打包、原生插件包生成、隔离无头启动、真实 WKWebView 场景、性能采样、安装和归属清理。

Tauri 主线程只处理窗口和原生 UI。异步 IO 由 Tokio 执行；SQLite 使用独立 Rust oc-data-worker 子进程，所有请求仍经过统一有界资源池，禁止用 spawn_blocking + timeout 假装终止同步查询。worker设定SQLite hard_heap_limit/cache/busy/progress-handler边界；Hermes读取heap8MiB/cache2MiB，本地事件heap16MiB/cache1MiB，3s执行截止。取消必须终止并wait该工作进程、排空stdio后才归还租约。同步查询不会进入Tauri主线程。

数据库worker不安装系统常驻服务；初始实现保留每项请求独立执行的强隔离，后续只有测量证明需要且预算/取消等价时才改驻留池。内置插件使用同一生命周期及资源契约；外部官方插件使用独立原生子进程。采集在途合并、慢周期跳过；取消撤销发布权后等待真实IO结束。关闭先停admission，再排空插件、worker、监听器和原生对象。IPC保留按分区更新与来源心跳，不恢复全量快照广播。

类型与 IPC 契约

保留现有前端业务 DTO 和可见结果语义，Rust serde 类型使用 camelCase；输入使用 deny_unknown_fields 和显式长度/枚举校验。公开 Rust 类型与 TS 类型通过契约夹具验证 JSON 字段、null/缺失和错误语义；不建立逐函数跨语言桥接。

五组有限 API 全部迁移：MonitorApi（含历史、事件、诊断、导航与订阅）、SettingsApi、UpdatesApi、MarketplaceApi、StartupRecoveryApi。新的 Tauri 命令逐项校验窗口标签、当前已登记窗口身份、主帧来源、恢复/退出阶段与参数。Tauri capability 仅授予本地应用窗口必要事件能力；不授予前端文件、shell、通用进程、任意URL或任意 Rust 执行能力。外部导航和新窗口默认拒绝。

主窗拥有变更能力；托盘只能读快照、刷新和请求受限主窗导航；恢复窗只有三项恢复操作。headless 在原生边界拒绝显示窗口、Tern跳转、登录项与通知权限请求。订阅独立解绑，销毁/重载清理；异步监听注册尚未完成即取消时，注册完成后也必须立即解绑。

完整42方法、逐窗权限、取消/订阅所有者、监听就绪屏障及登录/恢复/持久事件验收，冻结在 api-contract.md。React挂载前完成Tauri事件监听；同步本地订阅之后的snapshot必须等待宿主interest握手，避免监听建立期间丢更新或旧snapshot覆盖新分区。单向cancel改成可等待Promise，全部消费者接住真实失败，不保留旧通道。

原生插件协议与包

采用受信任官方独立可执行插件，不使用Rust动态库ABI或JS引擎。.ocplugin为ZIP，内部是有代码签名封装的.ocbundle；manifest放在Contents/Resources，由Apple资源封印覆盖，避免裸二进制签名没有认证manifest。正式在线包必须通过完整Developer ID信任验证，并与已经验证的当前宿主Team、固定插件Bundle ID一致；摘要、manifest版本/权限/入口和实际Mach-O架构同时检查。每次启动复验已安装包，不信任可写安装目录中自报的摘要。

无Developer ID的本地构建只允许执行本构建资源目录中固定摘要的离线包；在线可执行安装明确禁用，不接受远端ad-hoc包。验收包使用仅在测试feature编译的独立摘要信任根，生产不得包含测试信任根。无需生成或保存新的发布私钥；正式在线发布仍需要Developer ID凭据，当前不宣称已具备。

完整协议冻结在 plugin-contract.md：版本2、有界NDJSON、独立控制读循环、请求ID/代次、host-IO分块与结束确认、取消/stop可抢占、所有宿主IO走唯一资源池；常驻插件槽和协议缓冲单独计入同一预算账本，不长期占一次性命令槽，避免嵌套死锁。插件不继承凭据环境，官方SDK不支持自行spawn/daemonize；可信原生代码不是沙箱。

包预算明确为archive≤2MiB、manifest≤16KiB、入口≤8MiB、总展开≤9MiB、条目≤16、中央目录≤64KiB；安装最多16包，所有已安装/下载/展开暂存/回滚合计≤32MiB。每次解压写入复核实际累计量，安装前预留完整事务峰值。上述为必须证明的上限，不表示当前原生产物已构建合格；真实release系统插件测量不合格则先修订并评审，不能静默放宽。

当前CJS包只作移植依据；新宿主明确拒绝旧格式。安装目录版本化，旧包与个人数据不自动删除。

数据与资源约束

保留已有 JSON 设置与 SQLite 业务存储格式中仍有效的字段及事务，不引入历史格式转换脚本或兼容路径。新插件包格式独立；旧 Electron专属状态不加载。

输入兼容的是仍有效的公开业务契约，而非旧执行路径：ID字符上限按原JS UTF-16 code unit计算，字段另设UTF-8字节上限；Hermes时间排序保留UTC秒与纳秒，不降为字符串或毫秒比较；原始stderr、prompt、工具参数与结果正文不进入快照。任何清理失败优先于取消报告。

持久目录显式沿用旧应用实际使用的 ~/Library/Application Support/OC Chan（已核对原宿主app.setName('OC Chan')及userData用法），保留设置、事件数据库、游标与通知claim，不能依赖Tauri默认目录碰巧一致。仅开发实例使用隔离目录，不读正式数据库做写入验收。新插件目录单独版本化，旧包不自动删除。

监听就绪与首个快照

  1. desktop-api.ts 在React挂载前初始化当前窗口允许的Tauri事件监听；全部 listen() 完成后才能挂载正常页面。恢复入口只初始化恢复API。
  2. UI的subscribe向本地listener集合同步加入监听，并产生幂等退订函数；仅首个订阅/最后退订改变宿主兴趣。宿主interest只有一个在途更新和一个最新待提交状态，不能无界排队。
  3. snapshot() 等待当时已请求的interest更新被宿主确认后才读快照。全局Tauri监听早已存在，因此注册期间不会丢更新；消费者保留现有“期间已更新分区不被旧snapshot覆盖”逻辑。
  4. M/T分别登记updates/sources；sources只有M可订阅。internal monitor_subscription({updates,sources}) 不是42个业务方法之一，不能由renderer指定其他window。
  5. 生产推送要求原生可见且未最小化、当前document已登记且有对应订阅。测试headless仅绕过原生可见性条件，仍要求显式订阅；测试文档可见性和暂停状态继续驱动UI订退订。
  6. 退订即刻移除本地listener；宿主迟到事件不能回调已退订组件。文档重载/窗口销毁撤销整个登记。React StrictMode反复mount/unmount不增加常驻监听数量。
  7. 初始注册失败阻止页面进入正常就绪，展示真实连接错误；不使用轮询snapshot或默认假数据兜底。

登录与启动恢复

登录启动由系统真实状态判定，不接受普通页面伪造。此启动不创建主窗，本次运行关闭Dock和防休眠但不覆盖持久偏好，仅创建托盘。用户打开主窗复用当前应用；requires-approval不等于enabled。

普通启动设置读取只有ENOENT使用默认值；坏UTF-8/JSON、权限、FIFO、链接、身份变化进入恢复流程，原文件不覆盖。真实隐藏recovery场景使用验收专用配置创建隐藏恢复WebView；生产headless读取失败仍明确失败退出，不冒充已验证恢复UI。恢复窗口拒绝所有普通commands，修复文件后的并发retry只初始化一次；quit/close先撤销启动权，晚到retry不得复活应用。

事件与通知持久不变量

事件数据库保持既有application/schema ID、库身份、DELETE journal、revision CAS、checkpoint+events原子事务及查询触发保留裁剪的revision变化。tombstone最多32768并推进floor；删除/淘汰后不能重放旧异常，stable upper与keyset分页不重复、不跳过已冻结范围。数据库替换和游标断档必须可见。

通知claim写入私有0600日志并fsync先于原生show；未确认投递在重启后不重放。库identity变化重置正确cursor，同实体5分钟冷却与每分钟3条分别有界，恢复事件可解除冷却，静默/睡眠后的摘要保留上限。显示暂停不影响通知；停用事件/关闭通知/退出按各自生命周期取消并排空。journal或原生handle关闭失败优先于取消，禁止假成功。

包认证与文件布局

.ocplugin为ZIP，唯一根目录<id>.ocbundle，其中只有Contents/Info.plist、Contents/MacOS/collector、Contents/Resources/manifest.json及codesign生成的Contents/_CodeSignature/CodeResources。目录项允许，其他入口/可执行文件/资源拒绝。Info.plist固定CFBundleExecutable=collector、CFBundleIdentifier=local.oc-chan.plugin.<id>，版本与manifest一致。manifest使用apiVersion=2与target=aarch64-apple-darwin。

manifest位于Apple签名资源封印内；正式候选验证完整bundle签名、所有架构、Apple Developer ID信任、固定Bundle ID，以及与已完整验证当前宿主相同的Team ID。不能用codesign display字符串替代签名验证。宿主只信已绑定的catalog字段，安装/更新必须同时匹配版本、权限、入口、目标、大小和SHA256。

离线bundled包的可信摘要随宿主资源封装，允许ad-hoc本地构建执行这一精确构建产物；ad-hoc宿主不接受网络原生包，UI明确说明正式签名要求。正式在线包使用上述Developer ID链，manifest也受封印保护。重启前重新校验原始已安装archive及展开内容与对应可信根，私有安装目录中记录的digest不能自行成为信任根。验收feature可编入独立fixture摘要根，发布禁用该feature且产物无测试根。

安装目录私有0700、文件0600、执行入口验证后0700；NOFOLLOW/NONBLOCK/EXCL、普通单链接，读取前后核验dev/ino/size/mtime/ctime。stage文件与目录fsync后再提交，失败清理不能静默忽略。

消息与双向分派

协议使用有界NDJSON。每帧编码后≤64KiB（包含换行、JSON转义和信封）；二进制chunk为base64，原始块≤16KiB。每条消息必须有v:2与generation；collect有单调call，host IO另有io。安全整数范围与过期代次明确校验；未知消息、重复完成、错序chunk、旧代回复视为协议失败，不伪造成功。

方向消息语义
host→plugininitialize可信id、appVersion、generation、受限能力和协议预算
plugin→hostready确认当前代初始化完成；不得自行修改权限
host→plugincollect本代唯一采样call和剩余deadline
plugin→hostioRequest绑定call/io的宿主命令、受限文件或socket请求；参数、总输出和deadline在准入前冻结
host→pluginioChunkstdout/stderr/data、连续seq、base64块；写入遵守背压
host→pluginioEnd最终字节总量、退出状态/身份；仅实际子进程与stdio结束后发送
host→pluginioError有界错误码；失败/取消不能产生ioEnd成功
plugin→hostresultChunk/resultEnd采样结果UTF8 JSON分块，连续seq、声明总量≤1MiB、最终摘要；宿主有界重组后校验业务DTO
plugin→hosterror有界采样/协议错误，不含敏感原始输出
host→plugincancel撤销指定call的发布与新IO权利，必须能在等待IO时处理
plugin→hostcancelledplugin已排空该call；host仍要等待自己启动的IO真实结束
host→pluginstop关闭新工作，撤销全代，清理并退出
plugin→hoststopped插件业务清理结束；host最后仍wait进程与管道

读循环、写队列与collect执行分离；插件不能在等待hostIO结果时停止读控制帧。每插件一个collect、最多8项hostIO，写队列最多4个编码帧；读缓冲最多一帧。stdin/stdout使用流式读取，换行超过64KiB立即失败；总结果超过1MiB立即拒绝。stderr每代保留≤64KiB，超限明确失败。

SDK只提供已授权的固定命令和只读路径能力；host按manifest能力重新校验，不接受通用shell。环境从明确白名单创建，不复制宿主完整环境或凭据。官方插件禁止自行spawn、daemonize、改变进程组或创建未登记常驻资源；这是一方代码契约，不称作OS强制隔离。

全局准入与取消

唯一资源账本同时管理原有command/file/socket预算，以及pluginProcesses≤16、pluginProtocolBytes≤8MiB；不能为每个插件另开独立“全局”池。插件进程槽不占一次性command槽，插件等待IO时不持该IO的另一个lease，避免嵌套申请。

协议的队列/读缓冲/结果重组在启动或collect前预留；原始hostIO输出与插件重组是两份内存，均计入申请，base64/JSON暂存以最大帧预留。原有4MiB ps输出通过ioChunk传输，不放宽帧限制，也不截短合法结果。

host启动的每项命令登记pluginId/generation/call/io/pid/birth/pgid；它可能不是plugin子进程，取消不能只杀plugin进程组。取消顺序：撤销发布和新IO准入→取消该call所有已登记IO→发送cancel→等待IO/stdio/插件确认。deadline到期按已登记身份终止并wait；归属不明时保留诊断，不按PID或进程名盲杀。清理失败使代次不可重启、文件不可卸载，应用退出继续清理其他插件并聚合失败。

安装事务

沿用download/validate→pending fsync→stop旧代→current改rollback→pending改current→按目标分区启用状态注册→删除rollback的提交顺序。安装与设置启停共用串行协调锁，提交依据锁内一致状态：启用时启动新代并等待真实首采样成功；停用时只验证静态契约并登记dormant，不spawn、不initialize、不采样即可提交，后续显式启用再真实初始化，失败如实报告。下载和验证阶段旧版继续工作；下载或签名错误不停止旧版。激活失败先排空新代再恢复旧目录与runtime；停不掉不得删除文件或并行运行另一版。

恢复记录绑定目录和archive身份；启动存在rollback优先恢复旧版并显示interrupted，只有pending无current恢复未安装。损坏包保持已安装标记且可显式卸载。卸载stop完成后进入文件删除提交阶段，此后取消不留下半删除状态。close关闭准入并等待单事务真实结束。

前置证明：真实system插件SDK请求4MiB输出、collect期间cancel/stop、乱序/超帧/截断、管道背压、宿主IO子进程回收、100启停后预算归零；真实release包大小与签名资源覆盖；篡改manifest/入口/版本拒绝；启用和停用两种状态下的安装、升级失败回退、设置切换竞争、取消、重启恢复与卸载；停用安装全程没有插件进程或采样。

持久事务

独占安装锁属于目标目录，锁文件和父目录验证私有/合法身份；当前目标、暂存、备份、父进程都绑定realpath及dev/ino或pid/birth。用户取消仅能发生移交前；进入替换后按事务完成或恢复，不能半途丢弃。

在目标同卷创建私有事务目录，记录UUID、预期版本、目标/旧包/新包身份、父进程出生身份、各阶段和摘要；记录原子写+fsync，阶段转换同时fsync父目录。阶段：

  1. prepared：验证旧/新签名与身份并预留空间；旧应用仍运行。
  2. waiting-parent：业务已关admission、排空真实任务；助手再次验证父身份并等待退出，超时不替换。
  3. backup-intent / old-backed-up：先持久化源/目标身份与备份意图并fsync，再核对身份执行旧包rename、fsync目录，最后记录完成；记录落盘后到rename前、rename后到完成记录前都允许崩溃恢复。
  4. install-intent / new-installed：先持久化暂存到正式目标的意图、身份和摘要，再rename、fsync目录并记录完成；旧包仍保留。
  5. verifying-startup：使用唯一事务UUID和私有回执路径启动新应用；等待真实就绪。
  6. committed：验证就绪后持久提交，才允许清理旧包和事务目录。
  7. rolling-back / rolled-back：启动失败、超时或验证不符先停止且确认新实例身份/退出，再恢复旧包；恢复失败保留两份现场并非零退出。

崩溃恢复同时检查写前意图和实际身份，接受操作尚未发生与已经发生两种合法组合：waiting-parent/backup-intent时若登记旧包仍在目标则保留，若旧包已在登记备份且目标缺失则恢复旧包；old-backed-up/install-intent时若登记新包仍在stage且目标缺失则恢复旧包，若登记新包已在目标则按未提交新版停止并回滚。new-installed/verifying-startup没有持久commit一律恢复旧包；committed只保留已验证新目标并清理登记备份。回滚rename也遵循写前意图、目录fsync和幂等身份判定。真正未知身份或不可能组合才停止并保留现场，不将正常崩溃窗口误报为篡改。恢复不需要运行不可信candidate。
