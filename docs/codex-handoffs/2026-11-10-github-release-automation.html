修复依据

  • 原流程只在版本标签推送时发布，普通 main 构建的附件留在 Actions 中。现已接通 main 的预览发布。
  • GitHub 按标签查询的 REST 接口不返回草稿。现通过 GraphQL 获取草稿 ID，再按 ID 验证附件与公开状态；相应测试已改为真实接口契约。
  • 锁测试的 Python 子进程在 CI 超时。现用已有原生工具链查询真实 POSIX 锁，保留持锁、子进程退出及解锁断言。
  • download-artifact v8 把单个匹配附件直接展开到下载目录，原发布脚本多找了一层子目录。工作流改为按确切名称下载，并显式指定脚本读取的目录。
  • 插件收到 I/O 完成消息后，旧任务的额度尚未释放，下一请求会被误拒。现在先回收任务并归还额度，再发送完成消息；预算不变，错误继续保留。

Release 先创建草稿，全部附件核对通过后再公开；预览标签绑定完整构建提交，既有 Release 和附件不覆盖，稳定 Latest 不被预览版替换。

本地定向检查、云端构建与真实应用验收、公开发布与匿名下载均已核对。正式签名、公证及已安装应用的原地升级尚未验收，本轮没有替换本机正式应用；无头验收不包含可见原生窗口和 OS 通知投递。
