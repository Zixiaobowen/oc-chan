# 开发与维护指南

面向贡献者与维护者的构建、发布、数据边界和验证说明。使用介绍见 [README](../README.md)。历史验收记录只代表对应版本和场景，不代表当前版本全部通过。

## 运行

需要 Node.js 22.12+、npm 和包含 macOS 26 或更新 SDK 的 Xcode Command Line Tools（构建原生窗口导航程序、Liquid Glass 与通知权限模块）。打包后的应用不需要本机安装编译器；原生液态玻璃需 macOS 26 或更新版本。

```sh
npm install
npm exec -- install-electron
npm run dev
```

锁定的 Electron 45.2.1 npm 包提供独立的 `install-electron` 命令；仅安装 npm 依赖还没有可运行的 Electron。首次安装或全新 `npm ci` 后显式准备二进制，命令使用锁定版本及包内校验和。CI 在需要运行真实渲染 smoke 时执行同一步骤。

`npm run dev` 默认以无头模式运行真实 Electron 主进程、采集、IPC 与渲染器：不显示窗口、Dock 或托盘，不弹原生错误框，也不允许跳转并激活其他应用。可通过终端输出的本地 `DevTools listening` 地址进行页面操作和截图；原生窗口始终不可聚焦。无头启动只编译原生玻璃模块，不编译窗口导航程序；错误仍写入终端，不能把无头截图当作 Dock、托盘、原生焦点或可见玻璃合成效果的验收。

每次启动自动创建独立的 `.dev-instances/instance-*`，隔离构建输出、Vite 缓存、配置与会话数据，并记录启动器进程与工作目录的归属；开发服务器和调试端口由系统分配。主进程／preload 支持热重载，多个实例不会争用正式应用的单实例锁。按 Ctrl+C 结束时终止本实例子进程并清理临时目录；配置只在该实例存活期间保留，不读取或改写正式安装的个人设置。异常未退出的进程会明确报错并保留其目录，不能在进程仍使用目录时手动删除。

开发实例统一使用无头模式。只有用户明确要求原生窗口交互时才使用：

```sh
npm run dev:window
```

该模式同样隔离数据与构建目录，但会显示窗口并启用正常 Dock／托盘行为。需要主进程调试时，可使用 `npm run dev -- --inspect`，Node Inspector 同样分配独立本地端口。

使用 Node.js 24 运行真实渲染主链路验收：

```sh
npm run smoke:renderer
# 指定尚不存在的证据目录：
npm run smoke:renderer -- --out /tmp/oc-chan-renderer-smoke
```

入口复用无头开发启动器、真实 preload／IPC／React 和有界测试夹具。Agent、launchd／cron 与 Hermes 配置是明确标识的合成输入，系统指标由本机真实采集；不借用个人设置、任务数据库或会话。检查概览对象直达、Hermes 历史支持／不支持、来源故障恢复、IPC 失败与恢复、历史取消、Agent 详情 Esc 焦点、事件重复100次采样及插件重建去重，以及设置保存后在新进程重新读取。第二次启动使用第一轮实际保存的设置内容，仍创建独立 profile，不复用个人数据或浏览器存储。

完整流程还覆盖3D办公楼定位、页面与2D/3D切换后的视角保留，以及带旧视口的2D显式定位与详情关闭焦点。整组交互限时300秒，包含启动和重启的总时限420秒；单步RPC与条件等待仍分别限时5秒和8秒，长耗时历史读取等场景保留各自明确上限。

验收先将唯一无头窗口的原生内容区设为1280×860并回读，再设置CSS视口；不能只扩大CSS模拟尺寸，否则较小云端显示区域可能使输入坐标超出实际滚动区域。后续880×640与200%文字检查仍由CDP/CSS控制。窗口始终隐藏且不可聚焦，原生窗口尺寸与CSS视口分别记证，不代表可见macOS窗口验收。

事件页验收使用临时库追加5000条合成记录，检查每页50条、来源／类型／发现时间筛选、真实任务历史直达、失败翻页重试与返回、后台新记录保持阅读位置、SQLite锁下查询取消和恢复、停用及覆盖断档，并核对1280×860、880×640与200%文字。文本编辑和按钮使用CDP输入；阅读位置通过真实记录的DOM `scrollIntoView`设置，再检查后台刷新前后的记录身份、像素位置和输入焦点。下拉选项采用DOM选择后验证真实React状态与IPC查询；这些检查不计为macOS原生滚轮或菜单键盘验收。

通知专项可用 `npm run smoke:renderer -- --scenario notifications --out /tmp/oc-chan-notification-smoke`。它检查默认关闭、Hermes完整身份订阅、来源与类型、静默时间草稿、真实写入拒绝后的回滚与焦点恢复、插件启停、中英文880×640/1280×860与200%文字、独立重启读取；时间字段采用DOM原生setter，不声称验收了macOS分段输入。无头实例明确返回系统通知不支持，始终不发送OS通知。

插件市场专项使用 `npm run smoke:renderer -- --scenario marketplace`，覆盖首次未安装、真实包安装／卸载、下载取消、更新代码执行、损坏包拒绝、激活失败回滚与独立重启。非市场的系统指标验收在隔离 profile 中显式安装随包插件；生产入口首次不自动安装。

失败返回非零并保留阶段、诊断与截图；`--fault fixture` 和 `--fault ipc` 用于验证故障不会被误报通过。正常退出后核对本实例进程与临时目录清理，清理失败同样不能通过。它不执行任务、不发送通知、不打开可见窗口或跳转其他应用；不能替代原生 select、VoiceOver、Dock、物理托盘和可见动画验收。`npm run smoke` 继续用于当前机器真实采集源的只读检查，和这条隔离集成验收分开。

24小时常驻验证使用同一个性能入口，先运行6分钟预验，再运行真实24小时；`--out`必须是尚不存在的目录：

```sh
node scripts/performance/run.mjs --mode smoke --scenario soak --sampler admin --out /tmp/oc-chan-soak-preflight
node scripts/performance/run.mjs --mode baseline --scenario soak --sampler admin --out /tmp/oc-chan-soak-24h
```

`--sampler admin`只将本次只读进程采样器交由macOS系统认证启动，Node驱动与Electron必须保持普通用户；不要用sudo启动整个性能入口。采样器通过私有本地socket校验驱动PID、UID与出生身份，限定到该驱动启动的应用进程树，读取其setuid系统命令的资源；不安装常驻服务、不修改sudoers、不读取目标进程参数或环境。认证等待最多120秒，取消、拒绝与断链明确失败；owner退出后通过连接关闭或约1秒周期的身份检查终止采样。普通用户模式`--sampler user`是默认值，但本机setuid子进程的字段会被系统拒绝，不能用于声称完整进程树验收；两种模式都保留短命进程漏采和生命周期缺口。

长测使用独立合成输入、真实Electron采集与IPC：32会话每秒更新、配置变更、会话换代，每小时插入128会话突发、100次刷新、200次历史替换、锁库恢复和四插件启停。通知保持无头不支持，核验真实认领日志和重复采集；日志以有界gzip保存，分钟心跳在`progress.json`，最终结果在`result.json`。源码变化、缺采样、预算超限和清理失败均明确失败。ESRCH确认的采样中退出进程保留空资源和CPU覆盖缺口；存活进程不可读仍中止。短测不代表24h、完整进程树峰值、系统通知、睡眠唤醒或16GiB硬件已经通过。当前证据见[性能基准](./performance-baseline.md)。

构建应用内容（不启动窗口）：

```sh
npm run build:app
```

打包 arm64 macOS 应用：

```sh
npm run package
```

产物在 `release/mac-arm64/OC Chan.app`，本机安装位置为 `/Applications/OC Chan.app`。本地打包执行 ad-hoc 签名，不具备 Developer ID 身份或 Apple 公证；应用内安装更新要求 Developer ID 签名版本，发布门槛见下文。旧版本的安装记录不代表当前合并版本已验收；更新功能原有验证与未覆盖项见 `docs/codex-handoffs/2026-11-05-app-updates.md`。

构建可下载的 DMG 安装镜像与 ZIP 应用压缩包：

```sh
npm run dist
```

文件名为 `release/OC-Chan-<版本>-mac-arm64.dmg` 和对应的 `.zip`。`build:app` 完成类型检查和 Vite 构建；打包器在隔离的 `.app` 内按目标架构及应用最低 macOS 版本编译 Swift 导航程序、N-API液态玻璃与通知权限模块，校验完整应用后生成DMG/ZIP。目录包和两份归档包含相同的完整应用，不依赖安装时重签修补。本地构建采用ad-hoc签名，不验证开发者身份，也不是公证；正式标签发布另须Developer ID签名和公证。`build:native` 仍供显式原生开发使用。Electron来自锁定依赖；`dist`只构建产物，发布由标签流水线负责。

## 本地交付与手动升级

本地交付提供arm64开发材料，与正式签名更新发布分开。当前维护者尚无Apple开发者账号，正式签名、公证、Release下载与真实升级仍未验收。使用Node.js 24及当前Mac的磁盘映像工具，从工作区构建一份可核对来源的交付；`--out`的父目录须存在，目标目录必须全新，已有材料不会被覆盖：

```sh
npm run delivery:local -- --out release/local-20261105-1
```

构建只在临时源码副本中进行，包含当前未提交的构建输入；`delivery.json`记录真实HEAD、分支、版本tag或null、dirty状态、输入摘要及逐文件来源清单。HEAD不代表未提交内容。临时副本先按原锁文件执行`npm ci`，依赖与许可证核对均留在副本目录内；构建完成后复核工作区来源，期间变化则失败，不生成成功清单。包清单包含文件、符号链接及空目录；ZIP逐成员核对类型、权限、长度、CRC和SHA-256，DMG验证校验和、只读挂载并核对包清单后卸载。单归档≤1GiB、成员≤20000、单成员≤512MiB，ZIP worker限时120秒；沿用应用内容与冻结体积门禁，不放宽预算。

目录包含arm64 DMG/ZIP、目录包、`source-manifest.json`、`validation-source/`、`package-manifest-arm64.json`、`dependency-review-arm64.json`、`SHA256SUMS.txt`和最终的schema 2 `delivery.json`。`validation-source/`只保留构建时的`package.json`、锁文件、包预算和两个Tern插件源文件，逐项绑定来源清单中的原路径、字节数和SHA-256，总上限28MiB，不导入或执行其中的源码。依赖审查基于本次构建的许可证清单、精确锁文件及真实npm公告查询；错误或未审查项阻止交付。清单记录实际codesign状态，公证为not-requested、Gatekeeper为not-assessed、安装为false，CI运行和正式下载地址为null。本地SHA-256只用于核对字节，没有开发者身份认证含义。失败记录在`failure.json`，不能将残留产物当作通过验收的交付。

手动升级按下列顺序操作；生成交付本身不退出或替换已安装应用：

1. 在交付目录运行`shasum -a 256 -c SHA256SUMS.txt`，核对`delivery.json`的版本、arm64、来源摘要和签名状态；缺文件、哈希/大小不符、坏ZIP或DMG时停止。未签名或ad-hoc不等于通过Gatekeeper，系统阻止打开时保留报错，不关闭系统防护。
2. 保留当前可用的旧`.app`及其版本信息，退出OC Chan并确认已退出。不要改动应用数据目录；安装包不包含个人设置、事件或上游会话数据。
3. 从已核对DMG或ZIP取出完整`OC Chan.app`，手动整包替换`/Applications/OC Chan.app`，不要合并新旧包内文件；本期仅M系列Mac。需要通过hook安装时，须独立确认该命令将安装的源码及替换范围，不能把它当作这个清单的安装回执。
4. 打开新包，确认实际启动路径、版本、界面、采集、任务历史和原设置，并检查托盘等原生交互。仅主进程存活不代表就绪；本次工作区的实际安装/原生回执仍待D-03专项。
5. 新包不能就绪时退出新包、恢复完整旧`.app`并保留错误信息和失败包供定位；不删除个人数据，不自动迁移设置。若旧包也失败，保留两次错误及现场，停止反复覆盖。新版验收成功后删除本次旧包和解包产生的额外应用，长期只保留`/Applications/OC Chan.app`。

也可用安装工具核验并安装已生成的交付目录。第一条仅核验来源、归档摘要、包内容与实际签名，不启动或替换应用；第二条会退出旧应用、整包替换`/Applications/OC Chan.app`并验证新包就绪，失败自动尝试还原。两条命令都使用Node.js 24：

```sh
npm run install:local -- --check-delivery release/local-20261105-1
npm run install:local -- --delivery release/local-20261105-1
```

schema 2交付只代表其`source.digest`对应源码；安装器核对交付内的来源快照，并用同一份已认证数据复验暂存包，当前工作区的版本、插件和预算变化不会改变历史交付的判定。缺少来源快照的schema 1交付明确拒绝，须重新生成；篡改快照、包或归档仍会失败。安装就绪协议保留完整的规范SemVer身份，包括预发布与`+build`组合；该身份校验不放宽正式发布的版本格式限制。升级失败保留暂存目录里的旧包/失败包、`installation-source.json`及独立启动回执位置；先核对错误和进程状态再处理。退出等待期间目标被其它任务替换时拒绝覆盖，不强杀正式应用，也不自行清除他人的安装锁。

本地工具不创建tag、推送、发布、检查更新或上传应用数据；应用离线行为沿用已有本地采集。后续正式发布需要独立版本与发布授权，不能用本地材料完成状态代替正式下载回执。

## GitHub Actions 构建、下载与发布

[Build macOS 工作流](https://github.com/Zixiaobowen/oc-chan/actions/workflows/build.yml) 在推送 `main`、创建或更新目标为 `main` 的 PR、推送 `v*` 标签时自动运行，也可在 Actions 页面选择 **Run workflow** 手动构建指定分支或标签。日常开发使用 `main`，开发分支通过目标为 `main` 的 PR 进入检查。

工作流使用 Node.js 24 和 `npm ci` 安装锁定依赖，在 `macos-26`（Apple Silicon）执行适用行为测试，使用提供 `NSGlassEffectView` 的 macOS SDK。涉及应用、界面资源、隔离启动／夹具、依赖或工作流的改动，另运行真实无头 Electron smoke。通过后执行类型检查、Vite构建、包内原生模块编译和arm64 DMG/ZIP打包，保留依赖许可证与安全公告、包内容及冻结体积门禁，最后生成并验证SHA-256。任一门禁失败都阻止上传安装产物，没有 `continue-on-error`；smoke失败证据仍上传并保留3天。同一分支或PR的新构建会取消旧构建；不同标签的发布作业共用串行队列，最多100个待处理作业，不替换已排队的标签。Actions固定提交SHA，构建作业权限为contents:read，只有发布作业获得contents:write；checkout不保留凭据。

`scripts/ci-tests.mjs` 以 PR 的 base SHA 或 push 的 before SHA 与当前 checkout 比较（保留完整Git历史），输出测试清单与选取原因。Agent、任务、系统采集包含对应模块和直接调用方；拓扑、查看状态、任务历史、设置、Tern导航分别映射已有行为测试；安装脚本或Git hook改动必跑临时目录中的安装事务测试。直接改动测试只选该文件。普通文档不跑产品测试；公共IPC/快照入口、依赖或跨模块入口扩大到对应套件。删除且已无原模块映射的代码检查跨模块调用方；新增测试、未知代码路径、缺失映射或无效基准明确失败，新增功能须同步此映射。标签、手动构建及无前序提交的新分支检查全部确定性测试。

本地可用 Node.js 24 执行 `npm run test:ci -- --plan src/renderer/src/AgentTopology.tsx` 查看单元测试选择与 `rendererSmoke` 标志，去掉 `--plan` 执行这些单元测试。测试进程并发上限为2；真实 Electron smoke 由独立步骤运行，不混进 Node 单元测试进程。纯文档、仅单元测试或安装脚本变更不额外跑 renderer smoke；标签、手动及无前序提交的新分支执行。真实个人环境 `npm run smoke` 不放进 CI。云端门禁以对应提交的实际运行回执为准，构建成功不能替代原生窗口、安装应用或真实个人数据源验收。

普通主线与PR构建保留 `oc-chan-package-checks-arm64-<运行编号>`，包含SHA-256、包内容和依赖审查报告，保留7天；它们仍真实生成并校验DMG/ZIP，但不重复上传大体积安装包。需要下载开发安装包时手动运行工作流，再从成功记录的 **Artifacts** 下载 `oc-chan-macos-arm64-<运行编号>`。手动构建的安装包保留3天，标签构建保留7天；每份包含arm64 `.dmg`、`.zip`、频道的 `*-mac.yml` 及上述三份报告。解压外层ZIP后执行 `shasum -a 256 -c SHA256SUMS.txt`。保留期只作用于新上传的产物，不会追溯清理历史积压；上传配额错误继续使CI失败，既有产物清理需要明确范围。正式GitHub Release附件不受Actions保留期影响。

也可通过已登录的 GitHub CLI 下载指定运行的全部产物：

```sh
gh run download <运行ID> --repo Zixiaobowen/oc-chan --dir downloads
```

源码仓库已公开；不要把源码或Actions产物当作私密存储。安装包和客户端更新统一发布在 [Zixiaobowen/oc-chan Releases](https://github.com/Zixiaobowen/oc-chan/releases)，客户端匿名读取，不内置GitHub凭据；发布说明面向使用者描述变更。普通分支、PR和手动构建仅作本地ad-hoc签名，不发布；缺少Developer ID签名或公证凭据的标签构建会明确失败，不发布不能原地更新的安装包。

### 发布签名更新

在本仓库的 Actions Secrets 中配置以下签名与公证凭据；不要把证书或密码提交进仓库：

| Secret | 用途 |
| --- | --- |
| `CSC_LINK` | Developer ID Application 的 `.p12` 证书，包含私钥；electron-builder 支持 Base64 内容 |
| `CSC_KEY_PASSWORD` | `.p12` 导出密码 |
| `APPLE_ID` | 用于公证的 Apple 开发者账号 |
| `APPLE_APP_SPECIFIC_PASSWORD` | Apple 应用专用密码 |
| `APPLE_TEAM_ID` | 10 位 Apple Team ID |

正式发布须单独获得版本发布授权；合并与推送分支不授权创建标签或发布版本。标签必须严格等于 `v` 加 `package.json` 的规范SemVer版本；允许稳定版及预发布版本，拒绝带 `+build` 元数据的发布版本，因为当前builder安全文件名与更新产物契约不支持该格式。获得发布授权后，将 `package.json` 和锁文件版本更新为尚未发布的更高版本并提交，再推送相应版本标签。已发布版本不覆盖。

```sh
# 示例：先将 package.json 和锁文件版本更新为 0.2.0 并提交，且确认该版本尚未发布。
git tag -a v0.2.0 -m "OC Chan v0.2.0"
git push origin v0.2.0
```

标签流水线在arm64原生架构上强制Developer ID签名、公证，并用 `codesign`、`stapler`、`spctl` 验证应用、Swift helper与两个N-API模块。发布作业逐一核对版本、架构、文件大小、SHA-512和SHA-256；稳定版生成含DMG与ZIP的 `latest-mac.yml`。先核对本仓库已存在触发构建的标签，再使用 `--verify-tag` 创建草稿，上传DMG、ZIP、一个频道元数据和 `SHA256SUMS.txt` 共四个附件，验证完整后才公开。上传后重新读取Latest，仅更高稳定版本设为Latest；旧稳定版和预发布不改变Latest，公开后读回Release身份、附件及Latest状态。缺失标签、已有同名Release或中断留下的草稿会阻止发布，失败保留实际远端状态及回查地址。所有发布者必须参与同一串行约束；外部手动发布不受此工作流锁保护。此流程尚无真实签名发布回执。

稳定版更新源只消费 `https://github.com/Zixiaobowen/oc-chan/releases/latest/download/latest-mac.yml`。预发布版本（如 `0.2.0-beta.1`）生成 `beta-mac.yml` 并标记为预发布，不会推送给稳定版客户端。`npm run dist` 始终使用 `publish: never`；真正发布仅由匹配版本的标签推送触发。发布作业将 GitHub Actions 自带的 `GITHUB_TOKEN` 作为 `GH_TOKEN` 传给发布器，只有该作业获得 `contents: write`；构建作业维持只读权限。

截至2026-11-08，公开的 `v0.1.0` 只有安装包和校验和，没有 `latest-mac.yml`。发布页可访问不代表自动更新已可用；需要先发布包含签名应用及更新元数据的新版本，才能进行真实升级验收。

### 应用内更新

签名的 macOS 安装版启动 30 秒后检查新版，之后每 6 小时检查，也可在设置页手动检查。手动检查会重置下次自动检查时间，避免启动定时器覆盖刚显示的结果或错误。发现新版时显示提示，由用户点击下载；下载完成后点击“重启并安装”，原生 Squirrel.Mac 验证应用签名并替换、重新启动应用。普通退出不会安装，并会清理临时下载包。已有未包含更新功能的旧版，需要先手动安装一个签名的新版本，之后才能验证原地升级。

更新插件只接受固定公开源，跟随 HTTPS 的 GitHub 发布域名跳转；无远程上报和内置访问令牌。元数据限 64 KiB，ZIP 限 512 MiB，下载流式写盘并验证精确大小与 SHA-512，空间不足时在下载前拒绝。一次只执行一个检查、下载或安装，检查限时 30 秒、下载 15 分钟、原生交接 120 秒；取消和退出会终止请求、清理临时文件及监听器。常规进度每 250ms 节流，完成时立即推送最终状态。错误保留在更新设置中，不能通过重启或忽略校验伪装成功。

开发模式及未具备Developer ID签名的macOS安装包（包括本地ad-hoc包）支持主动检查新版和失败后重试，但不自动检查，应用内下载及安装仍禁用并说明原因；非macOS仍禁用更新。签名检测异常会保留错误，不阻断后续手动检查。当前维护者尚无Apple开发者账号，真实签名、公证、公开版本发布与“重启后版本号变化”尚未验收；本地下载测试不能代替这些步骤。官方依据：[Electron autoUpdater](https://www.electronjs.org/docs/latest/api/auto-updater)、[electron-builder 更新元数据](https://www.electron.build/v26/features/auto-update/)，核对日期2026-11-05。

## 本机安装与推送后的清理

在需要自动更新本机应用的 macOS 克隆中启用一次：

```sh

```

该命令将本仓库的 `core.hooksPath` 设为 `.githooks`。之后向 `Zixiaobowen/oc-chan` 的 GitHub 仓库推送分支时，`pre-push` 会在上传前自动更新 `/Applications/OC Chan.app`，覆盖创建 PR 前的分支推送和已有 PR 的后续推送。仅本地 commit、网页创建 PR、没有新引用的推送、仅推送标签和删除分支不会触发安装；GitHub Actions 也不会修改本机应用。

hook从待推送提交导出独立源码快照，执行`npm ci`与`npm run package`，不混入工作目录的未提交改动。安装工具使用Node.js 24。它先核对来源、完整包内容、版本、arm64、实际签名类型、路径、写权限与可用空间；空间预留包含新包全部字节、每条目4KiB和64MiB余量。本地ad-hoc签名在打包时完成，暂存复制后重新验证，不改写已校验包；ad-hoc不代表Developer ID签名或Apple公证。

退出旧应用前完成预检与同盘暂存。整包替换后的成功标准是一份仅限本次启动的就绪回执：随机nonce、实际可执行路径、版本和PID一致，主界面、IPC、已启用采集域及可用Hermes历史均通过。主动停用的域记录disabled，尚未安装的系统插件记录not-installed，没有Hermes任务记录unavailable，不伪造采集或历史成功。就绪协议文件分别限8KiB、目录0700/文件0600，拒绝链接、过期或重复回执；应用内限时30秒，安装器总等待45秒，并确认回执PID仍是目标应用且再存活2秒。白屏、IPC/采集/历史错误或超时会触发还原。

## 功能与统计口径

- **协作拓扑**：识别 OMP、Codex、Claude Code、OpenCode CLI 的存活进程，排除运行时内部 worker；Codex 桌面后台服务仅在持有当前会话时显示节点。合并包装进程，展示 PID、工作目录和可读取的模型元数据。OMP 同进程子代理通过当前打开的会话、ownership 描述符与父会话的专用 artifacts 目录关联；Codex 从可写 rollout 的会话元数据关联父线程。普通 fork 仍是主会话，独立子进程保留进程祖先关系与资源指标，同进程子代理不重复分摊资源。协作拓扑页面以可交互画布展示父子关系，概览仍提供简短列表。
- **定时任务**：读取用户及系统 launchd 配置、当前用户 crontab、OMP / Hermes 任务元数据。周期和日历任务计入定时数量，包含停用配置；常驻服务和启动项另列。OMP 配置与对应 launchd Label 合并，Hermes 内部任务与其调度器分开标注。支持类型、范围、状态和名称 / 执行计划的组合筛选；结果栏可随时清除已设置的筛选，恢复默认任务列表并将焦点放回搜索框。
- **系统监控**：从插件市场安装后采集 CPU、实际使用内存、应用／联动／压缩内存分项、交换空间、数据卷磁盘空间、默认网卡上下行吞吐及趋势。CPU 和内存各自从同一次完整进程采样中取前十，支持切换排序；内存排行按常驻大小（RSS），不是对 CPU 前十重排。最近 60 次 CPU／内存／网络采样只保存在内存中。
- **数据来源**：逐项展示可见范围、错误与最近成功采样时间。尚无成功采样时，等待与失败状态均显示数量未知；来源失败不转换成零。调度配置读取或解析失败会保留整个上次快照及采样时间并显示错误，只有运行状态读取失败时才保留已知任务并标记状态未知。暂停显示只冻结界面，后台继续采样；切换页面仍使用同一暂停时刻，继续显示时接收最新状态。

更新方式：当前归属的 OMP 会话通过文件事件订阅更新，按 90ms 固定窗口合并后增量读取，磁盘耗时另计。跨会话读取完成后按 16ms 固定窗口合并发布，后续事件不延长截止时间；只保留各会话最新结果，复用未变化的 Agent 对象，停止或移除会话时取消旧批次。Agent 进程、资源与归属每 2 秒独立发现，系统每 2 秒采样，调度每 30 秒采样；同类发现请求合并。IPC 只发送有变化的数据分区，自动采集不反复切换加载状态，系统采样不会重绘 Agent 页。

主窗与托盘分别登记数据和来源心跳订阅，主进程最多保留两个自有窗口登记。隐藏、最小化或暂停显示时停止相应窗口的监控推送和数据重绘，活动到期计时也冻结；后台采集继续运行，不积压隐藏期间的快照。恢复先订阅再读当前快照，新到分区事件优先于较慢的旧快照；显示窗口不会解除用户主动暂停。重载清除旧文档订阅，窗口销毁与应用退出释放登记和监听。无头开发允许按文档可见性验收，但始终禁止原生显示和聚焦。

数据来源页按实际来源展示进程识别、工作／空闲、父子关系、近期调用、精确活动数量、执行历史与跳转能力及限制。已连接、无数据、部分可见、失败、未支持和用户停用分别显示；OMP 活动子代理仍为未知，只有 CLI 进程证据时不推断正在工作。概览的未知数量与详情中的状态原因可定位对应来源。

来源行分别记录最近尝试和最近完整成功；无变化的采样只推送有界时间心跳，不重复发送任务或 Agent 列表。来源页离开、暂停或隐藏时解除时间订阅，恢复读取当前时间。失败的 launchd 域只重试该域；其它可重试故障明确标为“重试所属分区”，仅刷新相应分区。重复请求合并，等待时保留按钮焦点；正常有限覆盖和未支持不提供虚假的修复按钮。

「数据来源 → 脱敏诊断」先生成可查看和选择的完整 JSON 预览，显示字节数、纳入/总数及限制，再由用户复制或选择本地保存位置；不上传、不额外采集。只导出现有内存快照中的应用/系统版本、来源能力/状态、受控错误码与时间、资源额度计数和对象总数，不含用户名、UID、绝对路径、标题、命令、环境、凭据、正文或原始错误输出。来源ID归一化；无法完整统计的总数显示未知，不冒充0。

每份报告最多256KiB、64个来源、128条诊断和32项资源；超限与无效字段有明确省略说明。全应用只保留一个预览、一个在途操作和一个10分钟到期计时器；关闭预览、离页、窗口文档销毁或退出会取消并等待本实例操作释放。复制等待Electron原生剪贴板确认；保存使用主进程系统对话框，0600权限临时文件完整写入后原子链接到新文件名，不覆盖已有文件或符号链接。取消/写入失败会清理本次临时文件，清理失败另报且阻止继续导出；成功写入后才显示成功。无头开发不弹系统保存对话框，文件事务通过受控选择器专项验收。

采集命令、文件读取与 socket 共用 `src/main/resource-budget.ts` 的全局额度：各最多 8 个在途，stdout/stderr 分别预留、合计最多 32 MiB；文件原始缓冲合计 16 MiB，socket 合计 512 KiB。等待队列最多 256 项、每来源 128 项，来源标识最多 32 种；同类资源按来源轮转，较大请求保留其轮次，防止被持续小请求饿死。携带文件输入的命令原子申请命令与文件两类额度，跨类按入队先后保留所需容量，取消或超时解除等待优先权。排队最多 10 秒，获准执行后才开始各命令原有执行计时；队列满、超时或请求超额均明确失败。plist 转换单流 4 MiB，launchctl 单流 8 MiB。

「数据来源 → 采集资源额度」显示当前槽位、字节预留、峰值、排队、拒绝数及排队/执行耗时；快照同时携带按来源拆分的只读数值。取消可移除未开始的请求；命令、文件和 socket 在真实关闭后才释放额度。文件用非阻塞打开并检查普通文件类型，拒绝命名管道/设备/目录占住读取槽位。长期文件监听不占短寿命读取槽位，仍受 128 会话上限约束。上述额度只计原始 IO 预留，不代表解析对象、缓存或全应用 RSS；长期压力验收由 R-04 单独跟踪。

停止监控先关闭入口并取消排队及在途采集，再等待文件、socket、监听器和本实例辅助子进程实际关闭；重复停止共享同一次排空，晚到结果不能发布。历史读取提供可等待的取消、idle 和 close。应用退出先拒绝新请求，等待窗口几何及已排队设置事务完成，再关闭仍可能被设置事务使用的采集插件和桌面效果；独立的导航、诊断和托盘同时清理。整个排空上限 5 秒；保存失败仍继续清理，失败或超时记录脱敏阶段、资源名及剩余额度，并以非零状态退出，不伪报释放成功。不会终止被观察的 Agent 或其它开发实例。通知随事件插件取消：停止接收批次、撤销未确认显示、关闭保留对象并解除电源监听；清理失败保留错误和有界句柄供重试，不能报告成功关闭。

默认网卡通过有界、可取消的 `route` 与 `netstat` 命令采样，只读取默认接口的链路计数，避免重复叠加地址行；首次采样、接口切换、计数器重置或读取失败后的首次恢复均显示速率未知，下一次连续成功采样后恢复速率。

CPU 差分基线、网络基线和最多 60 点历史绑定单个采集实例，销毁时清空。CPU 首次采样、计数回退或不连续时显示未知，下一次连续有效样本才显示数值；概览、系统页与托盘一致，走势图不会把未知值连到零。CPU 和 RSS 排行各最多 10 项。

调度目录用有界迭代读取：所有用户和系统目录合计最多 4096 个条目，包含被过滤的非 plist；配置、三个 launchctl 域、OMP、Hermes 与 cron 合计最多 4096 条任务、8 MiB 任务投影。来源记录最多 64 条、每条使用字段最多 4096 UTF-8 字节，日历条件及每条件字段各最多 64 项；公开任务标识长度限制同时生效。超限明确拒绝本轮，Monitor 保留上一完整快照及其时间，不将截断清单标为成功。

plist 原文件最多 1 MiB，通过普通文件描述符按初始大小分块读取，验证读取前后与转换后的身份，再把受限输入送入 plutil stdin；增长、替换或超限均拒绝。实例缓存按 dev/ino/size/mtime/ctime 失效，最多 4096 项、8 MiB（投影、路径键与固定元数据估算），单投影最多 64 KiB；删除文件回收额度，销毁清空。数据来源的「调度资源边界」显示扫描、任务和缓存额度，字节记账不等于 JS heap 或 RSS。

Agent 私有 host registry 枚举最多 4096 条（含非 JSON），超限不连接任何 host；最多读取 32 个 host、单记录 4096 字节，私有目录/文件权限、符号链接和真实进程身份检查继续生效。ownership 描述符及保留对象同样有合计数量和字段上限，错误不作为无活动证据；不扫描历史会话目录。

切换页面会保留本次主窗口会话的搜索、筛选、详情选择、页面滚动、系统进程排序及拓扑查看状态；返回时仍使用最新快照，失效对象清除选择并保留说明。搜索最多 1024 个字符。页面照常卸载，历史请求和页面监听随离页释放；不在后台挂载全部页面，也不缓存旧监控快照。重新加载或重启后恢复默认查看状态，已保存的外观与托盘组合不受影响。

左侧菜单栏可拖动右侧分隔线调整宽度：默认 214px，最小 188px，最大 320px；窄视口进一步收紧上限，为主内容保留至少 560px。Tab 聚焦分隔线后，可用左右方向键调整，Shift 加方向键加快，Home/End 到最小/最大；双击恢复默认，Esc 取消当前拖动。宽度自动保存，重启或重新加载后恢复已保存偏好。放大后的紧凑视口继续使用导航菜单，恢复宽窗时恢复所选宽度。

### 协作拓扑画布

节点代表采集到的 Agent，箭头按 `parentId` 从父 Agent 指向子代理。同一个 PID 不会自动产生关系；父节点缺失或关系成环时显示明确提示，不生成虚构节点。

OMP 节点优先用当前会话标题显示简短工作摘要，最多两行；概览列表同步展示，悬停或详情可查看完整标题，也可按工作内容搜索。标题随正常进程发现更新，使用当前标题槽而非可能过时的初始标题；移除终端专用图标，不读取聊天正文生成摘要。未提供标题时保留 Agent 名称，详情明确显示缺失。摘要用于识别会话工作主题，不代表当前执行步骤。

Codex CLI 与桌面版的当前会话也进入同一画布：从存活 Codex 进程持有的可写 rollout 文件读取首条 `session_meta`，以线程 ID 标识节点，按 `source.subagent.thread_spawn.parent_thread_id` 连接同进程或独立进程子代理，显示可用的昵称、工作目录和会话开始时间。普通 fork 的 `forked_from_id` 不建立协作关系；父会话未进入当前采样时保留缺失提示，不创建虚假父节点。桌面后台服务只有持有会话时才产生节点。

Codex 不扫描历史目录、不解析会话正文；支持标准 `sessions/YYYY/MM/DD/rollout-…jsonl` 路径（包括自定义 `CODEX_HOME` 和带 rollout ID 后缀的文件）。OMP 与 Codex 每轮合计最多读取 128 个会话头部，Codex 每个头部最多 1 MiB；格式损坏、超限或重复归属显示读取不完整。关闭会话文件或进程退出后，下次进程采样移除对应节点。保留的可写会话不能证明仍在执行，Codex 子代理与桌面会话显示状态未知；尚未接入其近期调用、模型切换或外部窗口跳转。共享 PID 资源不重复计算，多主会话共享宿主时不猜测各会话占用。

概览里的具体 Agent 或任务可直接打开该对象的详情；“查看全部”仍只切换页面。托盘展开“查看 Agent 与任务”可打开各前五个对象或完整列表，来源限制也可直接定位到来源行。导航携带对象身份，重复通知和普通采样不会重放定位；首次加载通过读取后确认消费避免丢失目标。目标被筛掉时保留当前条件并提供“清除筛选并定位”，身份变化或对象离开时说明失效，不选相似名称的对象。关闭详情后返回该页对应节点/行；目标已不可见则返回搜索框。

默认使用 3D 工程办公楼：一栋建筑对应一个项目，一个主会话协作任务对应一层；主 Agent 使用独立办公室，子 Agent 使用开放共享工位。项目按主 Agent 的完整工作目录划分（忽略末尾斜杠），不推测 Git 根目录；任务按真实父子关系归组，跨 cwd 子代理跟随主任务，并保留自身 cwd。缺父、循环或非 main 根分支明确标为待归属，不虚构办公室归属。选层会淡化其它任务、外立面和屋顶，以观察办公室和共享长桌；镜头不自动移动，可另用“聚焦楼层”。

鼠标拖动空白处旋转，Shift 拖动平移，滚轮缩放；方向键平移，Shift 加方向键旋转，F 适应全部建筑。拖动主 Agent 只调整独立办公室内工位，子 Agent 限制在本任务开放工位区。任务菜单按项目分组，员工菜单、楼层标牌、可见员工支持定位及详情。手动工位按任务中心的局部坐标保存，项目重新排布不改变工位；工位、任务选择和镜头跨页面及 2D/3D 切换保留，重载后恢复默认。关闭详情后归还实际可见员工标签或画布的键盘焦点；员工标签优先于楼层和建筑标牌。不透明楼板／屋顶遮挡的员工不可被鼠标穿透选中，选层后的透明剖面仍可操作。

3D 单场景最多 1200 位员工、2400 条关系、400 万渲染像素，员工／楼层／建筑标牌合计最多 32 个；超限显示当前数量与限制，请调整筛选，不静默丢弃对象。员工菜单可访问全部当前员工。楼体和办公室使用共享几何与实例化网格，无常驻模拟；图形上下文丢失提供重试。离页释放 WebGL、几何、监听器和标签，静止场景无持续动画循环，隐藏时停止绘制。按需加载 Three.js 0.187.0 的独立 chunk，生产渲染代码压缩，开发源包和类型依赖不进入应用包，原有包体积预算保持不变。

可主动切换为 2D 卡片画布；以下布局、分页、项目色和流动连线说明针对 2D。两种视图共用筛选、真实关系、折叠、详情和 Tern 跳转；3D 的自然人物材质保持稳定，脚下标记及标签显示状态。定向真实 Electron 验收入口为 `npm run smoke:renderer -- --scenario topology`。

- 自动布局按分支根节点的完整工作目录排序，同项目的主 Agent 相邻并列，项目间留出更大间距，目录未知的分支放最后。同项目内按稳定标识排列，活跃状态与分支大小不影响顺序；子代理沿真实父子关系向下展开，跨项目子代理仍跟随父分支并保留自身项目色。
- 分页与画布采用同一项目顺序，每个分支内父节点优先，每页和每次布局最多 200 个节点（含上下文）。项目过大可跨页延续；分页栏显示本页／总展开节点数、本页／总匹配数和跨页关系数量。只绘制同页真实连线，跨页父节点可从节点上的链接定位。所有展开对象都可翻页到达，深链和环仍保留关系说明。
- 拖动空白处平移，滚轮或触控板捏合缩放，也可使用缩放按钮。首次进入或清除筛选优先展示当前页的首个项目组；搜索打开首个命中所在页并定位该节点。“适应视图”显示当前页全部节点。
- 拖动节点调整位置；普通采样更新与切页返回保留手动位置和视口。切换类型、活跃状态或搜索词时，清除旧手动位置，按当前可见节点重新排列并适应视图；清除筛选同样重新排列恢复的节点，避免留下隐藏节点的空位。“重新布局”也可主动清除手动位置并重排。位置与折叠状态各保留最多 4096 个节点、标识不超过 512 个字符；超限明确提示，离开完整快照的节点及时回收。只保存在本次窗口会话内，不写入 Agent 配置或磁盘。
- 节点宽度随文字尺度变化，高度由实际内容决定；布局、连线和选中显露共用实测尺寸。语言、字体或内容导致几何变化时重排，保留手动位置和当前视口；容器缩放不重新整理节点。“适应视图”和“重新布局”等待尺寸与布局同步后执行。尺寸通知每帧合并，每个节点最多保留一条；窗口隐藏暂停提交，恢复处理最新尺寸，离页取消待处理帧。
- 收起／展开分支控制显示范围。搜索与角色筛选保留匹配项的父链和子节点，额外节点标为“关联上下文”；筛选期间展开分支，避免隐藏命中项。清除筛选后恢复折叠状态。
- 同一项目的节点保持同色，项目按完整工作目录识别（忽略末尾斜杠）；目录缺失时显示中性卡片。颜色不随活跃状态、筛选或选中变化。工作中、空闲、仅进程存活、状态未知通过同色的不同形状标记和文字区分，近期调用另有文字提示；选中用外框，关联上下文用虚线。
- “活跃状态”提供全部、活跃、不活跃，可与类型及搜索组合。活跃表示工作中或近 6 秒收到调用事件，不代表调用仍在执行；不活跃仅包含明确空闲且没有近期调用的 Agent。仅进程存活或状态未知的 Agent 不归入不活跃，可在“全部”中查看。活跃筛选保留命中节点的父链与完整子树，空闲或状态未知的子代理仍可点击查看；不活跃筛选只补齐命中节点的父链。所有未命中的关联节点标为“关联上下文”，不计入匹配数。暂停显示时沿用冻结时刻，继续显示后按最新状态和事件时效更新。
- 点击节点或聚焦后按 Enter／空格查看详情；Esc 或关闭按钮返回原节点，原节点不可见或已消失时返回搜索框。首次进入时，自动适应视图保留用户明确选择的目标，待节点尺寸、布局与实际渲染位置同步后归还焦点；中途转向其他控件则保留新焦点。菜单打开时第一次 Esc 只关闭菜单，再按 Esc 关闭详情；应用统一管理选择，避免画布库延迟清除返回的焦点。选中节点提供当前项语义，方向键和 Shift 加方向键仍可移动节点。宽窗口在画布右侧显示详情，窄窗口在下方显示。
- 翻页保留已查看节点的手动位置和详情，选中对象位于其它页时可从详情定位回去；离开协作拓扑再返回时恢复页码、视口和选择。普通采样只更新状态，结构与实测几何不变时不调用布局。
- 右键 OMP 节点，或聚焦后按 Shift+F10／菜单键，打开操作菜单；首项“跳转到 Tern 标签页”会选中对应标签页并显示其原生 Tern 窗口。子代理沿已确认的父链定位所属主会话；当前节点已有精确pane时优先使用该目标，不依赖更上层会话仍然存活。跳转前重新校验窗口、pane 与会话文件，标签页已关闭、移动或更换会话时拒绝跳转，需刷新后重试。Esc 关闭菜单并回到节点；点击外部保持新目标的焦点。
- 父子连线保留实线箭头，并用连续流动的粒子表示父 → 子方向。流动部分加粗表示子节点有明确工作状态或近 6 秒调用证据，不改变颜色，也不代表某次调用仍在执行；普通数据更新不重建动画或重置进度。
- 暂停显示、窗口隐藏、动画离开可见区域时停止运动；系统启用“减少动态效果”时保留静态关系与状态文字。恢复显示读取最新快照，后台采集始终继续。

画布支持观察与跳转到对应会话，不能创建、删除或修改 Agent 父子关系。拓扑可见不代表子代理正在执行；活动数量的限制见下文。

首次跳转会安装应用内置的 `OC Chan Window Navigation` Tern 插件，给原生窗口标题加上明确的窗口标识，如 `[Tern "3"] Default`。插件仅格式化原生窗口标题，不改会话、标签页名称或聊天内容，也不增加持续轮询。安装目录固定为应用随包目录；拒绝符号链接、多余文件、超大资源或与内置manifest/脚本摘要不符的内容。安装后须确认固定插件ID、版本1.0.0、ready和window能力，失败不继续跳转。

随包Swift程序先筛选尚未退出、可交互的Tern应用（`activationPolicy=regular`）；后台/CLI进程及已退出项不参与歧义判断，多个可交互实例仍拒绝盲选。对唯一候选继续核验PID、实际bundle和可执行路径、Apple Developer ID签名，接受的bundle ID为`so.stencil.tern`、Team ID为`VTLHGQC72S`（2026-11-05核对本机实际签名）。PID绑定内核提供的启动秒和微秒，避免PID复用；不依赖经CLI或Tern自身重启时可能为空的AppKit `launchDate`。窗口key仅允许0–128个ASCII字母、数字、点、下划线和短横线；空key表示首窗，pane必须为正安全整数。导航最多并发1次、总时限10秒（含资源排队），每次复核身份和精确session后才focus，并将原生窗口回执绑定到同一PID和标题前缀。关闭主窗、renderer退出/重新导航或应用退出会取消在途工作并等待文件和子进程关闭。

原生程序通过精确应用与窗口菜单项显示目标，确认焦点持续稳定后才报告成功。辅助功能权限不足时不自动弹授权框；界面提示到系统设置中允许OC Chan后重试。外部错误通过统一脱敏诊断出口，不显示stderr、路径或会话正文。开发侧已验证受控完整链、真实只读身份/拒绝路径和headless禁止跨应用；2026-11-08经用户授权，已通过生产导航代码验证当前真实Tern会话标签页与原生主窗口焦点。全屏、跨空间切换及授权变更场景仍留在D-03专项验收，不以无头结果替代。

Tern更新后若仍运行已迁移或删除的旧应用，macOS可能无法取得运行进程的可执行路径或签名，导航会明确拒绝身份校验。此时需使用Tern的重启功能加载已安装版本；磁盘上新版应用的有效签名不能替代对实际运行进程的验证。

## 已知可见性边界

**目前不能准确报告 OMP 正在执行的子代理总数。** 完成后继续驻留的会话和lease不能证明仍在执行，应用保持“状态未知”和活动数`—`。2026-11-05已核对OMP18.16.0公开RPC、Collab与SDK：存在生命周期字段，但RPC面向其启动的会话，Collab元数据不含子代理清单，共享流又会同步正文，尚未满足既有本机会话的只读元数据接入边界。字段、身份和断线恢复缺口见[公开接口调研](./omp-lifecycle-research.md)。本期不实施适配器，没有改OMP配置、注入进程或启用Collab。

Tern `inspect` 按实际窗口列表读取并精确关联主会话，提供主代理的 working/idle 证据；其他 CLI 只有进程活性证据时标“运行中”。头部模型是会话初始模型，不能当作始终准确的当前模型。OMP 自定义会话目录、隔离 profile、其他用户 crontab、容器及第三方应用内部调度不在现有覆盖内。

近期调用只读取当前归属会话中的结构化工具／模型事件，输出工具名、模型标识和时间等白名单元数据，不输出提示词、参数或结果正文。每文件读取上限 128 KiB、最多订阅 128 个会话；不扫描历史目录。完成、取消、错误或超过 6 秒会清除调用提示。长推理尚未落盘、历史窗口不完整与不支持的运行时都可能没有近期提示，不能据此判断空闲或精确活动子代理数量。监听／读取错误明确显示，文件替换在正常发现时重新挂接，没有轮询兜底。

macOS 存在带未公开 `StartCalendarInterval.Second` 字段的系统任务：应用保留任务与原值，并提示字段是否参与实际调度未确认。不会推算 launchd / cron 的下一次运行时间。

launchd 的服务表与禁用覆盖分别读取：`?` 和括号标记不被当作退出码，也不使整个域失效。失败按命令、权限、超时、表结构、行解析或资源上限分类，只输出固定诊断代码、来源、阶段和时间，不返回原始命令输出。每域保留最后成功时间；失败表的旧条目仅用于保留对象，不作为本轮状态或 PID 证据。单表最多 8192 项、单个名称最多 1024 字节，命令最多 6 秒及 8 MiB 输出；超限明确拒绝不完整结果。

`MonitorApi.retrySource(sourceId)` 支持当前用户的 `launchctl:gui/<uid>`、`launchctl:user/<uid>` 和 `launchctl:system`，只重读指定域的两张表并合并已缓存配置；重复请求合并，不扫描其他配置或刷新 Agent／系统来源。一次运行状态重试不能清除尚未恢复的配置读取错误。来源页展示逐项重试及能力说明；停用来源不允许重试。

任务范围中的“当前用户”表示运行域，包含在该域中运行的 Apple 系统任务；“个人配置”按来源识别 OMP / Hermes 内部任务、当前用户 crontab、用户 LaunchAgents 中的 `com.user.` / `local.` 命名配置，以及指向主目录脚本的任务。脚本入口识别支持直接执行、常见解释器及 Python 无参数开关；不解析内联命令，也不把任意参数里的脚本路径当作入口。系统任务、应用更新器和 Hermes 调度器自身不纳入个人任务。macOS 没有逐项创建者记录，此分类不是创建者认证；无法确认的任务仍可在“所有范围”查看。归类在采集端完成，仅输出归类值，不输出脚本参数或环境变量。

状态筛选与列表徽标保持一致：运行中、等待触发、已停用、未加载、状态未知。“未知”不等于停用，最近非零退出码也不自动改写当前运行状态；查看最近退出码可打开任务详情。类型、范围、状态和搜索共同过滤结果，不会执行、停用或修改任何任务。

Hermes 当前状态结合 `jobs.json`、`executions.db` 与进程证据：已启用且排程中、没有在途执行或未清理心跳的任务显示“等待触发”；执行记录为 running、心跳在 300 秒内且 PID 的启动时间吻合时显示“运行中”。有效运行证据优先于暂停配置。任务已领取但尚未开始、心跳过期、PID 复用、数据库不可读或未知调度状态都保留“状态未知”，详情说明原因；不会因上一次执行失败就改写当前调度状态。详情独立展示最近执行成功、失败、投递失败或结果未确认，以及结果记录时间；没有历史时显示暂无执行记录。

Hermes 执行数据库通过 Electron 自带 SQLite 在独立、只读的短时子进程中查询，不依赖外部 Node、Python 或系统 SQLite，也不触发任务或修改调度数据。任务元数据单文件上限 1 MiB；每轮最多 256 个任务，数据库内按真实时间、原始时间文本和执行 ID 确定性选择每个任务的最新记录，累计历史数量不作为状态可用性的门槛。子进程每个输出流上限 4 MiB，SQLite 堆预算 8 MiB，获准执行后最多 3 秒，排队等待另计。超限或排序证据无效会明确报告采集不完整并保留未知状态，不截断后假称完整。采集与 launchd 查询并行，沿用每 30 秒刷新及同类请求合并。

任务详情从右侧展开，展示任务来源、执行计划、当前状态、配置路径及执行历史；点击整行或任务名称均可打开。历史按执行时间倒序，每页 25 条，支持刷新和前后翻页；每条显示执行结果、领取／开始／结束时间、耗时、执行 ID 和投递结果。执行记录中的“运行中”只表示数据库记录，不代表对应进程仍存活。

目前逐次执行历史接入 Hermes 的 `executions.db`。OMP、launchd 和 crontab 未提供该接口所需的逐次记录，详情明确显示来源不支持；这与 Hermes 的“尚无执行记录”、数据库读取失败分别表达。不会把最近退出码、计划配置或输出文件当作完整历史，也不读取提示词、错误正文、任务输出或聊天内容。

历史由任务插件显式注册 provider 并按需读取，最多一个在途请求和一个可替换的待处理请求。切换任务、关闭详情、切换页面、窗口隐藏或销毁时取消读取；重新显示后恢复。停用任务采集也会取消并等待历史子进程关闭，详情保留带采集时间的旧记录并禁止刷新／翻页；重新启用后重新读取，旧代请求不能覆盖结果。获准执行后最多 3 秒，等待全局额度另计且最多 10 秒；子进程每个输出流上限 128 KiB，SQLite 堆预算 8 MiB，请求偏移上限 100000。读取失败显示具体原因与重试入口；翻页失败可直接返回最近成功页，无需再次访问出错的数据库。

切页只保留历史页偏移和详情滚动位置，返回后重新读取同一任务的该页；记录变化导致该页为空时保留页码，提供上一页和返回首页。历史加载完成后恢复仍可到达的位置；用户主动滚动会中止待完成的恢复。返回的任务身份或页码不匹配时显示错误，取消后的晚到结果不会覆盖当前详情。

范围菜单按“配置来源”和“运行范围”分组，搜索使用当前界面显示的名称、来源与执行计划；英文界面的显示词同样可搜索。结果数量提供辅助技术状态播报，采样时间独立显示，不把暂停的快照描述成仍在更新。详情支持 Esc 或关闭按钮返回原任务；若原任务已被筛掉或移出快照，焦点返回搜索框。详情会说明任务已不在当前筛选结果中。键盘移向被详情遮挡的列表控件时收起面板并保留新焦点；翻页与重试将焦点移到执行历史标题。首次桌面数据连接失败时，任务区显示数据不可用与数量未知，避免一直停留在读取提示。

首次快照读取失败时，其他单个采样分区更新不会提前清掉整体错误；收到 Agent、调度、系统、事件四个分区，或完整快照 / 手动重试成功后才恢复。定时任务页点击重试会将焦点移到搜索框，错误提示消失后仍可继续键盘操作。

系统 CPU 是全机归一百分比；进程 CPU 按单核 100% 计，可能大于 100%。内存按 `Anonymous − Purgeable + Wired + Compressor` 页数计算，页大小从 `vm_stat` 读取。网络仅取默认接口，避免虚拟网卡重复计数。

## 本地异常事件

本地事件插件每30秒观察确认的 Hermes 执行失败、投递失败，以及数据源持续不可用和恢复。首次读取只建立历史基线，不把旧失败变成新事件；基线中最多128条未完成记录继续检查后续结果。来源须有新鲜、明确的错误证据持续60秒才记录不可用；停用、覆盖不足和超过120秒的采样间隔不推断任务失败。事件只保存固定标识、类型、发生／发现时间、结果代码与导航目标，不保存任务名称、参数、提示词、输出或错误正文。

Hermes 数据库始终只读；按数据库身份与 rowid 增量读取，轮转补查晚写入的结果，每次最多40条元数据，不以时间字符串作为唯一游标。七天范围之外、数据库替换、游标回退、未完成记录丢失和去重容量耗尽均保留覆盖断档。当前范围、排除水位及读取错误在「数据来源 → 本地事件」显示；事件插件停用会取消并排空其工作，重新启用恢复应用库中的游标。

应用自己的 `<userData>/events/events.sqlite` 使用0700目录、0600文件、原子事件／游标事务和稳定游标分页，每页最多50条，单条最多2KiB。保留期最多7天／10000条／20MiB（含日志），先到先清理并记录删除数量、截至时间与原因；主数据库上限8MiB、事件载荷3MiB，为索引和去重状态预留空间，DELETE journal与附属文件合计另受20MiB硬限制。最多16个存储请求、合计100条在途或排队事件，超过明确拒绝；有限子进程获准执行后最多3秒，SQLite堆16MiB，每个输出流256KiB。锁定、损坏、权限和空间不足明确报告，不重建或覆盖坏库。

已移除事件另保留最多32768条、最多7天的已处理标识。淘汰这些标识时原子推进排除水位，避免旧执行字段被改写后重复出现；代价是水位之前的后续变化不再补查，该排除范围写入持久覆盖断档。未淘汰范围内的同一执行和事件类型只记录一次，重启仍保持去重。本地通知默认关闭，与事件收集独立。

侧栏「事件」按精确来源ID、事件类型与发现时间筛选；编辑条件只修改草稿，点击应用后固定时间范围和分页上界。每页最多50条，分别展示发生与发现时间。后台发现新记录只显示提示并保持当前阅读位置；「刷新本页」沿用当前游标，「查看最新」才重新取最新上界。失败保留上次成功页和筛选，可重试原请求；离页、暂停和隐藏会实际取消查询，回来后读取成功页，不自动重放失败的翻页。

任务和Agent导航同时核对ID与身份；已消失或同ID身份变化时显示原标识及原因，来源导航沿用来源页失效说明。页面区分未启用、尚无保留记录、条件无匹配和读取失败；保留数量、删除范围与覆盖断档均标明读取时间，刷新才能重新核对该页信息。

## 本地通知

在「设置 → 本机通知」主动开启，选择来源或在Hermes任务详情订阅完整任务身份，再选择执行失败、投递失败、来源不可用／恢复类型。来源与任务任一匹配即可；取消来源不会移除单独任务订阅。整分区持续失败和实际来源都可订阅；cron／launchd没有逐次执行证据，不提供任务执行订阅。最多64个来源、24个任务，通知偏好最多48KiB，达到上限明确拒绝。

“打开系统通知设置”可进入 macOS 通知设置页，再选择 OC Chan；原有“请求或重新检查权限”保留。打开系统设置不代表已授权，失败在按钮附近显示；无头或非 macOS 环境禁用打开入口。

每滚动60秒最多显示3条（含摘要）；同来源和对象的连续故障冷却5分钟，恢复解除冷却。静默使用本地时间，支持跨午夜；时间编辑先保留草稿，再显式保存。静默、休眠和限流期间只保留计数，恢复后在下一轮事件采集汇总为一条，不回放所有旧通知。关闭通知或事件插件取消未完成工作并清除待汇总计数；事件列表继续按自身保留策略记录。

文案默认仅含OC Chan、事件类型与脱敏标识。显示任务名称需显式选择，并再次核对任务身份；不加入任务正文、私人路径或原始错误。点击才打开主窗口，复用现有目标身份校验；失效对象明确报错，摘要进入事件页。通知静音发送，不申请critical权限，不绕过系统专注模式；应用收到Electron的实际show回执才记为已发送，超时或失败标为未确认。

原生模块直接使用同一应用进程的UserNotifications权限。启动和普通刷新仅查询；只有用户按权限按钮才可请求授权。查询限2秒、显式请求限30秒、单条显示确认限3秒，整批限8秒。系统授权请求无法由应用强行取消：取消释放JS回调，但最多保留一个未完成OS请求，完成前拒绝新增请求并显示原因。系统异步回调按值持有共享状态，不能引用发起调用的栈变量；已用真实macOS权限查询验证101次异步完成和100次取消，无取消后的JS回调。授权弹窗、实际投递/点击、专注模式及休眠唤醒仍需分别验收，查询成功不能代替这些证据。

去重日志保存在`<userData>/events/notifications.json`，上限64KiB，目录0700、文件0600、同用户且单链接；现有不安全权限、硬链接或损坏数据明确拒绝，不自动修复或清空。发送前持久认领事件序号，确认后再更新回执；崩溃后的未确认批次不重发，以避免重复，但可能少发，界面会标明未确认。事件数据库替换会明确重置身份游标。最多一个100条批次、64个冷却项、3个发送时间与8个原生通知对象；文件操作使用共享资源额度，未启用时不创建原生适配器、监听或日志。

## 设置

左下角“设置”打开同页平铺的设置。外观、语言、文字大小和托盘行为直接使用行内单选框，液态玻璃使用强度滑杆，主题使用带配色缩略图的单选卡片，两种字体使用下拉框，登录启动、程序坞与防休眠使用开关。保存后的设置即时生效，主窗口与托盘小面板保持同步：

- 外观：跟随系统、浅色、深色。
- 液态玻璃：0–100% 整数强度，默认65%；0%关闭。使用 Apple 原生材质，仅侧栏、顶栏和托盘外层露出玻璃，数据内容区保持实色。强度通过原生中性色遮罩与界面遮罩共同调整通透程度；AppKit 没有公开的折射或模糊半径调节接口。拖动实时预览，松开保存；键盘调整停顿250ms后保存。Esc、失焦、隐藏或离开设置页取消未保存预览。每次最多一个在途预览和一个可替换的最新值；预览失败恢复实色并提供诊断与重试，保存失败恢复已保存值。
- 系统启用“减少透明度”或“增加对比度”时，玻璃自动停用并保留强度偏好；关闭这些系统选项后恢复。系统不提供原生玻璃时明确显示不可用。
- 主题：OC Chan、GitHub、Nord、Catppuccin、Solarized、Gruvbox。参考 Tern 的配色缩略卡片，悬停或键盘聚焦可预览整个主窗口，点击或用方向键／空格选择后自动保存。离开选择区、按 Esc、窗口隐藏或离开设置页会取消未保存的预览；浅色与深色各自记住主题，跟随系统时自动使用对应配色。默认均为 OC Chan。
- 语言：跟随系统、简体中文、English；任务名和会话标题保留原文，设置诊断只展示受控元数据。
- 文字大小：12 / 13 / 15 px，按同一比例调整界面的文字层级；侧栏辅助说明与计数不小于 12 px。
- 界面字体：系统默认、PingFang SC、Helvetica Neue。
- 代码字体：系统等宽、Menlo、Monaco，用于路径、PID 与代码等宽内容。
- 点击托盘图标：打开菜单栏下的小面板，或恢复并聚焦主窗口。右键菜单始终提供打开主界面和退出。

- 托盘面板：默认同时显示 Agent 与任务、CPU、内存、磁盘和网络的摘要；展开“显示内容”，可用复选框自由组合。每项指标可独立展开详情，多个详情可以同时打开；CPU／内存显示短时趋势及各自前五进程，内存有分项，磁盘显示数据卷容量，网络显示上下行趋势和实际接口名。组合保存在当前应用 profile 的本地存储中，关闭再打开、重载和重启后沿用；存储失败或无效组合会明确提示。折叠时不创建图表和进程榜；内容独立滚动，底部“打开主界面”固定可达。隐藏时停止面板数据订阅，重新显示时获取最新快照；后台采样继续。
- 托盘窗口按需创建：手动启动只创建主窗口，登录启动只保留菜单栏图标；首次请求面板才加载托盘页面。连续请求共享一次加载。页面加载与绘制就绪后再展示，超过10秒或加载失败会释放窗口并报告错误，下次点击可重试。正常隐藏保留已创建面板，退出时取消在途加载并释放资源。无头性能验收仅在开发配置中显式创建隐藏托盘，不增加正式IPC入口。
- 登录后启动：仅安装在“应用程序”文件夹中的 macOS 应用可修改自身的系统登录项。首次运行不自动注册；开关读取 macOS 实际状态，系统设置中的禁用不会被本地偏好覆盖。等待批准时保持未开启并提供取消请求；在系统设置中批准后可重新检查。登录启动不创建主窗口、不显示 Dock、不自动防休眠，仍可通过菜单栏打开界面。开发/无头实例禁止注册。
- 辅助功能权限：设置页被动查询当前进程的系统授权，用于跳转并聚焦 Tern；可直接打开“隐私与安全性 → 辅助功能”，仅打开页面，不自动授予权限。授权后回到设置页、窗口重新获得焦点或点击“重新检查”读取实际状态。开发实例的授权主体是 Electron。状态不写入设置文件；无头模式明确不可用且禁止打开系统设置。
- 显示程序坞：控制 macOS Dock 图标；关闭主窗口后仍在菜单栏运行，可重新打开。
- 防止休眠：运行期间阻止空闲休眠，关闭设置或退出应用时释放。不会阻止屏幕熄灭、合盖或手动休眠。

常规窗口按“设置名称 + 控件”排列；设置内容宽度不超过 560px 时，每项改为名称在上、控件在下，应用更新和偏好仍在同一页纵向滚动。主题卡片随设置容器宽度从三列调整为两列或一列。放大后主导航收进菜单，设置控件不会被替换或隐藏，焦点保持在原控件。

Agent 活跃状态、任务范围／状态和两项字体设置的下拉框使用统一箭头留白；中英文、深浅色及最小窗口 200% 缩放下保持箭头居中与文字避让，仍使用原生选择菜单。

侧栏宽度自动保存在同一设置文件中：拖动松开时保存，键盘调整稳定250ms后保存，双击恢复214px也会保存；Esc、失焦或隐藏取消正在进行的拖动。偏好严格限定为188–320整数CSS像素；窄视口可以临时限制实际宽度，扩大视口后恢复已保存偏好，不将临时限制写回。

主窗口保存正常态外框位置与尺寸（Electron/macOS逻辑像素，与页面文字尺度和页面缩放分开）。连续移动/缩放延迟250ms合并，最多一个在途和一个待写入值；退出时等待最后一次写入。重启按当前屏幕工作区限制尺寸和位置，显示器移除后重新定位；不恢复最小化、最大化或全屏状态。仅几何变化不会重建原生菜单或重新应用Dock/防休眠。侧栏和窗口保存失败在当前页面显示原因与重试，窗口本身保持当前几何，但不会声称未写入的值已保存；无头开发实例始终不显示或激活窗口。

登录项由 macOS 保存，不向 `settings.json` 添加第二份开关。回到设置页、窗口重新获得焦点或点击“重新检查”时读取真实状态；失败显示脱敏诊断，写入部分成功时尝试还原。还原失败仍显示实际状态并要求核对系统设置，不伪报保存成功。Electron 45 使用 `mainAppService` 与 `wasOpenedAtLogin`，不使用已移除的 `openAsHidden`。真实安装注册、系统批准与隔离账号登录尚待原生专项验收，开发夹具通过不代表这些场景已通过。

### 设置文件

偏好保存在应用用户数据目录的 `settings.json`，文件中的有效设置覆盖应用默认值，未配置项使用默认值；显式无效的值、未知字段及损坏 JSON 均报错。读取以 `O_NOFOLLOW | O_NONBLOCK` 打开，同一描述符核对普通文件，分块读取且最多64KiB；拒绝目录、FIFO、符号链接、读取期间增长或改变的文件，以及无效UTF-8。缺失文件仍是合法首次启动，损坏文件不会自动替换。保存串行执行，以0600独占临时文件写入、同步、关闭后原子替换；原生操作或写入失败时恢复原设置，回滚失败明确报错并退出。关闭、清理失败保留在错误链中。保存期间保留控件焦点，阻止重复提交；悬停预览不写入文件。

保存失败会在对应设置行下方说明路径冲突、权限不足、空间或配额不足、只读文件系统、超时等原因，展示本地完整设置路径与恢复步骤，排除故障后可重试同一修改。复制区使用 `src/shared/diagnostics.ts` 的白名单摘要，与主进程启动/退出日志共用出口：仅含允许的错误类型、代码、数值errno、失败阶段及受控元数据；设置资源表示为 `<appData>/settings.json`，不回显原始message、stack、stderr、命令或正文。错误链最多8层、16条、16KiB，循环/重复引用、深链、条目或字节超限、无法安全读取的字段会明确标记截断。若保存确认中断，则明确标为“保存结果未确认”，保留最近收到的实际设置，不将其误报为未保存。

手工修复前先在原路径之外备份。文件必须是 UTF-8 JSON 对象，最多64KiB；只允许下列字段，合法的缺省字段使用默认值，未知字段和非法值不会被忽略或迁移：

- `appearance`：`system`、`light`、`dark`；`language`：`system`、`zh-CN`、`en`。
- `lightTheme`、`darkTheme`：`oc-chan`、`github`、`nord`、`catppuccin`、`solarized`、`gruvbox`。
- `glassIntensity`：0–100的整数，默认65；0关闭，非法值直接报错。
- `textSize`：`small`、`default`、`large`；`uiFont`：`system`、`pingfang`、`helvetica`；`codeFont`：`system`、`menlo`、`monaco`。
- `trayClick`：`tray`、`main`；`showDock`、`preventSleep`：JSON 布尔值。
- `sidebarWidth`：188–320的整数；`windowBounds`：`null`或只含整数`x`、`y`、`width`、`height`的对象，坐标绝对值不超过131072，宽320–16384、高240–16384。实际恢复还受当前屏幕工作区约束。
- `plugins`：只允许 `agents`、`schedules`、`system`、`events` 四个 JSON 布尔字段，缺省均为 `true`。补丁按子字段串行合并；未知 ID 和非布尔值直接拒绝。全应用最多接受16笔设置事务（含在途），超出报告 `OC_SETTINGS_BUSY`。

### 启动恢复

可见应用读取设置失败时暂停正常启动，显示系统语言和系统明暗模式下的恢复页面。页面分别说明损坏 JSON、非法字段/选项、无效编码、超限、权限或文件路径问题，提供完整本地路径、人工修复步骤及可选择复制的脱敏诊断。不会改动原文件、重置偏好或应用部分无效设置；恢复期间采集尚未启动。

“重新读取”只访问固定的设置文件，并发请求共用一次有界读取。失败保留恢复页面并更新原因；文件合法后仅启动一次主界面与采集，撤销恢复接口并销毁恢复窗口。macOS在窗口交接间隙继续运行；关闭恢复窗口或选择“退出 OC Chan”则等待在途读取结束后退出，不会因迟到结果恢复启动。无头开发遇到相同故障只输出受控诊断并失败退出，不创建恢复窗口。首次缺失设置文件仍正常使用默认值。

### 采集插件生命周期

设计参考 [DeepSeek Harness 架构](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/architecture.md) 与 [Cordis Primer](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/cordis-primer.md)（2026-11-09 核对）：通过公开服务组合能力，并让注册与生命周期资源随停用撤销。OC Chan 复用自身已有的采集调度器与资源预算，不引入 Cordis 依赖、配置解释器或第三方插件安装器。系统监控是首个同时拥有采集与呈现的完整插件；Agent、任务与事件继续复用已有实现。

新增受信任插件时，先定义插件拥有的快照类型与轻量元数据，再加入统一目录，并提供主进程工厂和 renderer 贡献入口。系统插件可作为范例；页面、概览和托盘业务留在插件目录内，宿主只负责贡献的挂载、错误展示和卸载。不要通过修改 `App` 或 `TrayView` 的按名称分支接入新插件。

插件工厂取得宿主提供的取消信号、受预算约束的命令与资源服务以及快照发布能力。加载完成后仍须检查取消，停用不允许迟到的异步结果重新创建实例或注册页面。插件不得自行启动不受预算约束的命令，也不得直接读取另一个插件的私有对象。JS 模块可由运行时缓存，但停用必须撤销活跃贡献、取消在途工作并释放实例资源；模块缓存不代表插件仍在运行。

注册表最多接受16个插件，注册时检查稳定ID、能力名、采样周期、超时、重复ID、依赖环及最多16个可重试来源。所有内置来源使用同一公开契约：工厂按需创建，通过 context 取得取消信号、共享资源预算和快照发布入口；历史通过显式能力读取和取消。保持原采样节奏，在途采集合并，逐来源重试按声明 ID 合并并串行执行；慢采样跳过重叠周期，手动刷新不推迟下一周期。增量 Agent 发布和单来源重试不会清掉整轮采集错误，也不会虚增其它来源的成功时间。

「数据来源」按监控插件目录提供开关，采集偏好默认开启；系统监控需要先从插件市场安装。任务执行历史和 Hermes 异常读取随定时任务采集启停，本地事件还有独立开关；这些开关只控制 OC Chan，不改变上游 Agent 或真实任务。设置保存失败会恢复原启停状态，重试入口保留焦点。停用保留带时间的旧快照；卸载系统插件则移除采集与界面贡献并清空系统快照，保留采集偏好。暂停显示仍是独立行为，不等于停用采集。

停用立即取消该代工作，等待真实采集与清理结束后才报告已停用；重新启用创建新实例，重建 CPU、网络与趋势基线。迟到结果不能发布到新代次。启动或采集超时立即报告 ETIMEDOUT 并撤销发布权，但真实工作结束前仍保留资源归属。动态注册等待首次真实采集成功，卸载等待在途工作和 stop 排空；失败保留错误及安装文件，应用退出继续清理其他插件并汇总失败。未安装或未启用插件不创建采集实例及周期计时器。

2026-11-09 插件迁移已通过定向测试、类型检查与生产构建，并在独立无头 Electron 中验证系统停用/启用、20 次反复启停、24 次并发刷新合并和退出资源清零。主窗口与托盘 smoke、880×640 内容区交互也已覆盖。短时采样不代表长期无泄漏或性能提升；命令、证据路径、前后测量局限及未覆盖场景见[插件迁移交接](codex-handoffs/2026-11-09-plugin-system-monitor.md)。


### 插件市场与分发

`npm run build:plugins` 从 `src/plugins/system-monitor/main/index.ts` 与 `manifest.json` 构建 `out/plugin-market`，生产打包将目录与包放入 `Contents/Resources/plugin-market`。`node scripts/build-plugin-market.mjs plugin-market` 生成提交到官方源的文件。

首个包为 `system@1.0.0`。`.ocplugin` 包含 schema、manifest 和单文件 CommonJS 代码，入口为 `createPlugin(sdk)`；SDK 复用宿主全局预算与可取消资源服务。安装文件位于 `<userData>/plugins/system.ocplugin`，重启重新读取与校验。仅支持可信官方代码；模块白名单不是安全沙箱，声明能力也不等于 macOS 权限隔离。

在线源固定为 `https://raw.githubusercontent.com/Zixiaobowen/oc-chan/main/plugin-market/catalog.json`，目录与包须真实发布才可访问。应用附带的包可离线安装；网络错误明确展示。目录最多 256 KiB／64 项，单包最多 2 MiB、代码最多 1 MiB，已安装最多 16 包／32 MiB；同一时刻只允许一个事务，限时 30 秒。下载有界并校验字节数、SHA-256、manifest、平台和宿主／API 版本，再停止旧插件；激活失败恢复原版，取消等待流和事务清理完成，回滚／清理错误保留诊断。

### IPC 通道与边界

正常应用提供监控、导航、偏好及订阅通道，启动恢复阶段只注册恢复通道。所有请求拒绝多余参数；文本ID非空且不允许控制字符；先完成来源、窗口权限和参数验证，再执行下列副作用。拒绝信息仅含固定类别/消息，不回显未知键、URL或其他输入。

- `monitor:snapshot`、`settings:snapshot`：主窗口/托盘，无参数，只读当前快照。
- `plugins:snapshot`：主窗口／托盘，无参数；`plugins:check`、`plugins:cancel` 仅主窗口、无参数；`plugins:install`、`plugins:update`、`plugins:uninstall` 仅主窗口，接受一个最多 48 字符的插件 ID，不接受路径、代码或 URL；`plugins:changed` 推送市场状态并可独立解绑。
- `recovery:snapshot`、`recovery:retry`、`recovery:quit`：仅当前恢复窗口主帧，无参数；只读受控故障信息、合并重读固定设置文件或退出。该页面不暴露监控或设置bridge；正常启动后撤销三个handler。
- `monitor:refresh`：主窗口/托盘，section可省略或为`agents`/`schedules`/`system`/`events`，只刷新对应采集。
- `settings:update`：仅主窗口，单个普通对象，仅接受现有设置字段、严格枚举/布尔值及188–320整数侧栏宽度；拒绝未知字段、特殊原型及原型污染字段。窗口几何仅由主进程采集，Renderer不能通过此接口写入；通过后才进入串行原生效果与本地保存事务。
- `settings:retry-geometry`：仅主窗口，无参数，重试保存当前正常窗口几何，不接受路径或坐标；返回确认快照或受控写入错误。
- `settings:update-login-item`：仅主窗口，只接受一个严格布尔值；只修改当前安装应用的 `mainAppService` 登录项，不接收 bundle 路径。开发实例由主进程拒绝，无头实例在 IPC 边界即拒绝；返回实际系统状态和受控失败诊断。
- `settings:request-notification-permission`：仅主窗口、无参数；必须先启用本地通知和事件采集。显式请求／重查系统权限，返回真实通知状态；headless在IPC边界拒绝。
- `settings:show-main-window`：主窗口/托盘，可省略目标；目标仅有页面、Agent、任务或来源四种结构。页面包括 overview、监控插件页面、plugins、sources、settings；Agent ID最多512、任务ID最多256、来源ID最多128、对象identity最多16384字符；来源section使用监控分区枚举。显示主窗并提交一个可替换导航目标，不接受任意URL、文件路径或命令。
- `monitor:navigation`、`monitor:acknowledge-navigation`：仅主窗口；前者无参数读待处理导航，后者接受正安全整数sequence；过期确认不能清掉新导航。
- `monitor:retry-source`：仅主窗口，ID最多128字符；限定实际支持的 launchd 域，或当前快照中明确可重试的故障来源对应分区。其它来源标识被拒绝，不解释为任意命令。
- `monitor:focus-agent-in-tern`：仅主窗口，Agent ID最多512字符，仅从当前快照定位；之后进入有界Tern身份、资源与会话校验，不接受renderer提供的安装路径、可执行路径或命令。
- `monitor:schedule-history`：仅主窗口，任务ID最多256字符，Hermes前缀后的ID最多128；offset默认0，范围0–100000且必须为25的倍数。任务必须存在于当前快照，之后才读对应只读历史；共享上限同时用于IPC、读取器、Hermes provider和页面。
- `monitor:cancel-schedule-history`（send）：仅主窗口、无参数，只取消该主窗口的历史读取；托盘/未知窗口不能取消可信在途请求。
- `monitor:events`：仅主窗口，查询可省略或为普通对象；只接受来源ID、四种事件类型、规范UTC时间范围和非负安全整数游标。固定每页50条，拒绝自定义页大小、路径及未知字段；查询在事件插件停用时拒绝。
- `updates:snapshot`、`updates:check`、`updates:download`、`updates:cancel`、`updates:install`、`updates:release-notes`：仅主窗口、无参数，复用 `assertIpcSource` 并拒绝多余参数；分别读取状态、检查、下载、取消、显式重启安装和打开受限发布说明。`updates:changed`向主窗口推送更新状态，preload订阅独立解绑。无头模式拒绝打开外部发布说明。
- `diagnostics:generate`、`diagnostics:cancel`：仅主窗口，无参数；生成唯一有界预览，或取消并等待释放。`diagnostics:copy`、`diagnostics:save`仅接受当前预览的36字符UUID，不接受JSON、路径或任意选项；过期/替换的预览ID拒绝操作，保存位置仅由主进程系统对话框取得。
- `monitor:changed`、`settings:changed`向主窗口/托盘推送；`monitor:sources`仅向主窗口发送分区与来源的采样时间，`monitor:navigation`仅向主窗口发送导航通知。每个preload订阅返回独立解绑函数，解绑不再接收后续通知。

无头开发模式额外拒绝修改登录项、显示主窗口和Tern跳转，即使调用来自合法主窗口。新导航、来源重试、插件或事件通道必须补充同一校验入口、此清单及CI测试映射；不暴露通用`ipcRenderer`、文件访问或命令bridge。
